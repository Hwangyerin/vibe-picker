# todo-commit — Todo 마무리

중간고사 과제는 README에 **Todo 리스트의 변경 내역**을 반드시 넣어야 하고, 작업 중 **일정한 간격으로 push**해야 하며, 커밋 메시지에 **무엇을 했는지**가 드러나야 한다.
실습(v1) 때는 PRD와 Todo가 구현과 어긋난 채로 진행되다가 마지막에 몰아서 고쳤다. 이 스킬은 그 기록을 **Todo 하나 끝낼 때마다** 남기게 만든다.

## 전제

- Todo를 완료로 체크하기 전에 아래가 끝나 있어야 한다.
  - 화면·동작이 바뀌었다면 `browser-qa` 통과 (❌ 없음)
  - 디자인 관련이면 `ai-tell-check`에서 "높음" 없음
- 통과하지 못했으면 체크하지 말고 사용자에게 남은 문제를 알린다.

## 절차

### 1. TODO.md 체크

- 해당 항목의 `[ ]`를 `[x]`로 바꾼다.
- 계획대로 했다면 여기서 끝. 계획과 다르게 했다면 항목 끝에 `→ 변경: <한 줄 요약>`을 붙인다.

### 2. 변경 내역 기록 (계획과 달라졌을 때만)

TODO.md 맨 아래 **"Todo 변경 내역"** 표에 한 줄 추가한다. 구분은 네 가지다.

| 구분 | 언제 |
| --- | --- |
| `[추가]` | 처음 계획에 없던 항목을 새로 넣음 |
| `[변경]` | 항목의 내용·방법·우선순위를 바꿈 |
| `[삭제]` | 항목을 빼기로 함 (하지 않기로 한 것으로 이동) |
| `[테스트]` | browser-qa / ai-tell-check / 사용자 테스트 결과 때문에 바뀜 |

```
| 날짜 | 번호 | 구분 | 처음 계획 | 바뀐 내용 | 이유 |
| 10-31 | 9-4 | [테스트] | 서랍을 오른쪽 패널로 | 아래에서 올라오는 시트 | 390px에서 패널이 화면을 다 가림 (browser-qa) |
```

- **이유**는 반드시 쓴다. "더 좋아서" 대신 무엇을 보고 바꿨는지 쓴다.
- 새 항목을 추가했다면 해당 단계 목록에도 번호를 붙여 넣는다 (예: `9-12`).
- 기능 범위가 바뀌면 PRD.md의 "v2에서 달라진 것" 표도 함께 고친다.

### 3. 커밋

- 하나의 Todo = 하나의 커밋. 여러 Todo를 한 커밋에 섞지 않는다.
- 메시지 형식:
  ```
  <type>(<Todo 번호>): <무엇을 했는지 한국어로>

  <왜/어떻게 — 필요할 때만 1~3줄>
  ```
  - type: `feat`(기능) · `design`(화면·스타일) · `fix`(버그) · `refactor` · `docs` · `chore`
  - 예: `design(8-3): 모션 토큰 정의 — 호버 140ms, 전환 240ms, 감속 곡선`
- 스테이징은 파일을 이름으로 지정한다. `git add -A`나 `git add .`는 쓰지 않는다.
- 커밋하면 안 되는 파일: `.claude/settings.local.json`, `.claude/worktrees/`, 루트의 작업용 이미지(`image.png`, `color_saved.png` 등)
- 커밋 전에 `git status --short`로 의도한 파일만 들어갔는지 확인한다.

### 4. push

- **단계(stage)의 마지막 Todo를 커밋했을 때** push한다.
- 단계가 길어서 Todo 4개 이상이 push되지 않고 쌓였으면 단계 중간이라도 push한다. (일정 간격 push 조건)
- push 전에 `git log origin/main..HEAD --oneline`으로 올라갈 커밋을 확인하고, 사용자에게 목록을 보여준 뒤 올린다.
- push 후 GitHub Pages 반영까지 1~2분 걸린다. 단계가 끝났다면 배포 링크에서 `browser-qa` 시나리오 1, 2를 한 번 더 확인한다.

### 5. 보고

사용자에게 짧게 알린다.

```
✓ 9-4 완료 · design(9-4): 서랍을 바텀 시트로 변경 (a1b2c3d)
  변경 내역 1줄 추가 [테스트] · push 대기 2개 (9단계 끝나면 push)
  다음: 9-5 빈 서랍 안내
```
