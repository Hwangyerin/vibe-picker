# ai-tell-check — AI 티 점검

VibePicker는 "AI가 만든 화면의 AI 티를 줄이는 도구"다. 도구 자체에서 AI 티가 나면 설득력이 없다.
실습(v1) 때 목업이 "돌아가지만 AI 티가 나서" 전부 다시 그렸던 경험을, 감이 아니라 기준표로 고정하기 위해 만든 스킬이다.

## 언제 쓰나

- 디자인 관련 Todo(8단계 디자인 시스템, 9단계 화면 개편 등)를 완료 처리하기 **직전**
- 새 컴포넌트나 화면을 처음 그렸을 때
- 사용자가 "AI 티 나?", "점검해줘"라고 할 때

## 입력

1. 점검할 대상: 화면(스크린샷) 또는 파일 경로(`index.html`, `css/*.css`)
2. 가능하면 `browser-qa` 스킬로 찍은 스크린샷을 함께 본다. 코드만 보고 판단하지 않는다.
3. 기준 문서: `docs/design-system.md` (토큰·컴포넌트·모션 규칙)

## 점검 기준

각 항목은 **예/아니오로 답할 수 있게** 적혀 있다. "아니오"가 하나라도 있으면 지적한다.

### 1. 색
- [ ] CSS에 HEX/RGB 값이 직접 쓰이지 않고 모두 `tokens.css`의 변수를 거치는가
- [ ] 강조색이 한 화면에서 한 가지 역할(주요 행동)에만 쓰이는가. 모든 버튼·링크·아이콘이 같은 강조색이면 실패
- [ ] AI 기본값 색(`#3B82F6` 계열 파랑, `#8B5CF6` 계열 보라, 보라→파랑 그라데이션)이 없는가
- [ ] 회색이 순수 회색이 아니라 팔레트 색조를 살짝 머금었는가 (`--neutral-*` 토큰 사용)
- [ ] 글자 대비: 본문 4.5:1, 큰 글자·아이콘 3:1 이상인가

### 2. 타이포그래피
- [ ] 글자 크기 단계가 타입 스케일 토큰(`--text-*`) 안에서만 쓰이는가
- [ ] 제목과 본문의 크기 차이가 1.5배 이상으로 위계가 분명한가
- [ ] 굵기가 400/500/600/700 중 2~3개만 쓰이는가 (전부 600이면 실패)
- [ ] 숫자·HEX 코드는 고정폭 숫자(`font-variant-numeric: tabular-nums`)인가
- [ ] 한 줄 길이가 본문 기준 45~75자 안인가

### 3. 레이아웃
- [ ] 간격이 4px 그리드 토큰(`--space-*`)으로만 정해지는가
- [ ] 모든 요소가 똑같은 카드·똑같은 간격으로 반복되지 않고, 관련된 것끼리 가깝고 아닌 것끼리 먼가 (근접성)
- [ ] 화면마다 가장 먼저 봐야 할 요소가 하나로 분명한가
- [ ] 모든 것을 둥근 카드 + 그림자로 감싸지 않았는가 (카드 남용)

### 4. 컴포넌트
- [ ] 브라우저 기본 `alert`/`confirm`/`<select>` 모양이 그대로 노출되지 않는가
- [ ] 버튼에 hover / active(press) / focus-visible / disabled 상태가 모두 있는가
- [ ] 포커스 링이 키보드 사용 시에만 보이고(`:focus-visible`), 지워지지 않았는가
- [ ] 아이콘이 한 세트(같은 선 굵기·크기)로 통일됐는가. 이모지를 아이콘 대신 쓰지 않았는가
- [ ] 비어 있는 상태(empty state), 불러오는 상태(loading), 오류 상태가 설계됐는가

### 5. 문구
- [ ] "손쉽게", "한눈에", "간편하게", "혁신적인", "~의 모든 것", "지금 바로 시작하세요" 같은 상투 문구가 없는가
- [ ] 버튼 문구가 "확인"이 아니라 결과를 말하는가 (예: "프롬프트 복사")
- [ ] 같은 대상을 같은 이름으로 부르는가 (서랍/보관함/저장소가 섞이면 실패)
- [ ] 문장 끝에 불필요한 느낌표·이모지가 없는가

### 6. 모션
- [ ] duration과 easing이 모션 토큰(`--dur-*`, `--ease-*`)으로만 정해지는가. 모든 전환이 `all 0.3s ease`면 실패
- [ ] `transition: all`을 쓰지 않고 바뀌는 속성만 지정했는가
- [ ] transform/opacity만 애니메이션하는가 (width/height/top/left 애니메이션 금지)
- [ ] 호버는 짧고(120~160ms) 등장·전환은 그보다 길게(200~320ms) 위계가 있는가
- [ ] `prefers-reduced-motion: reduce`에서 움직임이 꺼지는가
- [ ] 모든 것이 fade-in으로 등장하지 않는가 (등장 모션은 화면당 1곳 정도로 아낀다)

## 진행 방법

1. `docs/design-system.md`를 읽어 현재 토큰 이름을 확인한다.
2. 대상 CSS에서 기계적으로 잡을 수 있는 것부터 grep으로 확인한다.
   ```bash
   grep -nE '#[0-9a-fA-F]{3,8}\b|rgb\(' css/*.css | grep -v tokens.css   # 토큰 밖 색
   grep -n 'transition: *all' css/*.css                                   # transition: all
   grep -nE 'alert\(|confirm\(' js/*.js                                   # 기본 대화상자
   grep -n 'prefers-reduced-motion' css/*.css                             # 모션 줄이기 대응
   ```
3. 스크린샷을 보며 눈으로만 판단할 수 있는 항목(위계, 카드 남용, 문구)을 점검한다.
4. 아래 형식으로 보고한다. 칭찬은 쓰지 않고 고칠 것만 쓴다.

## 출력 형식

```
## AI 티 점검 — <대상> (<날짜>)

| 심각도 | 기준 | 위치 | 문제 | 고칠 방법 |
| --- | --- | --- | --- | --- |
| 높음 | 색-2 | css/components.css:42 | 모든 버튼이 --accent | 보조 버튼은 --neutral-* 테두리로 |
| 중간 | 모션-1 | css/layout.css:88 | transition: all .3s | --dur-fast, transform만 |

통과: 색 4/5 · 타이포 5/5 · 레이아웃 3/4 · 컴포넌트 4/5 · 문구 4/4 · 모션 5/6
```

- 심각도: **높음**(첫인상에서 AI 티가 바로 남) / **중간**(보면 느껴짐) / **낮음**(다듬기)
- 높음이 하나라도 있으면 해당 Todo를 완료로 체크하지 않는다.
- 점검 결과 중 실제로 고친 사례는 README "스킬" 항목의 사용 사례로 남길 수 있게 `docs/qa/ai-tell-log.md`에 한 줄씩 추가한다.
