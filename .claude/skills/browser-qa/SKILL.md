# browser-qa — 브라우저 직접 점검

실습(v1) 때 "AI가 완료라고 했지만 직접 눌러 보니 틀린" 문제가 여러 번 있었다. 다크 모드에서 역할 배지가 라이트 색으로 남던 버그가 대표적이다.
코드를 읽는 것만으로는 보이지 않는 문제를 잡기 위해, **완료라고 말하기 전에 반드시 실제 브라우저에서 눌러 본다**는 규칙을 절차로 만든 스킬이다.

## 언제 쓰나

- 화면이나 동작이 바뀌는 Todo를 완료 처리하기 **직전**
- 단계(stage)를 마치고 push하기 직전 (전체 시나리오 실행)
- `ai-tell-check`에 넘길 스크린샷이 필요할 때

## 준비

1. 로컬 서버를 백그라운드로 띄운다. (ES 모듈이라 파일을 직접 열면 동작하지 않는다)
   ```bash
   python3 tools/serve.py        # 캐시를 끈 서버, http://127.0.0.1:8000
   ```
   기본 `python3 -m http.server`는 쓰지 않는다. 캐시 헤더가 없어 브라우저가 **고치기 전 CSS를 계속 쓴다**. (8단계 점검 때 v1 base.css가 그대로 적용돼 아이콘이 300px 검은 덩어리로 보였다.) 이미 캐시가 남은 포트라면 다른 포트(8001 등)로 띄운다.
2. 브라우저 자동화는 Claude in Chrome(`mcp__claude-in-chrome__*`)을 쓴다. 쓰기 전에 `claude-in-chrome` 스킬을 먼저 불러온다. 새 탭을 만들어 `http://127.0.0.1:8000`을 연다. (이 환경의 Chrome은 `localhost`로 열면 연결에 실패한 적이 있다)
3. 스크린샷 저장 위치: 작업용은 스크래치패드, README에 쓸 것만 `docs/qa/<단계>-<화면>-<너비>.png`로 남긴다.

## 점검 매트릭스

| 너비 | 대표 기기 | 라이트 | 다크 |
| --- | --- | --- | --- |
| 1440px | 노트북 | 필수 | 필수 |
| 768px | 태블릿 | 필수 | 선택 |
| 390px | 휴대폰 | 필수 | 필수 |

각 칸에서 확인할 것:
- 가로 스크롤이 생기지 않는가
- 글자가 잘리거나 겹치지 않는가
- 버튼을 손가락으로 누를 수 있는 크기(최소 40px)인가 (390px)

## 핵심 시나리오

변경한 기능과 관련된 시나리오는 매번, 전체는 단계가 끝날 때 실행한다.

1. **첫 화면** — 처음 열었을 때 무엇을 하는 도구인지 보이고, 샘플 사진을 눌러 시작할 수 있다
2. **사진 올리기** — 파일 선택과 끌어다 놓기 모두 동작, 3초 안에 팔레트가 나온다
3. **팔레트 스타일** — 스타일을 바꾸면 5색이 바뀌고, 사이트 강조색도 함께 바뀐다
4. **다시 뽑기 / 보관** — 매번 다른 조합, 보관한 시안을 누르면 그때 상태로 돌아온다
5. **스포이드** — 칩 선택 → 사진 클릭 → 색 변경 + my pick, 다시 뽑기에도 유지
6. **역할·대비·모드** — 랜덤 섞기 경고, 대비 슬라이더, 라이트·다크 전환이 목업·배지·HEX에 모두 반영된다
7. **브랜드 설정** — 강조색·톤·서체(추천 표시)·아이콘 세트와 굵기·둥글기·워드마크를 바꾸면 브랜드 보드에 바로 반영된다
8. **적용 화면** — 보드 / 모바일 웹 / 슬라이드 전환, 같은 설정 변경이 모바일 웹과 슬라이드에 똑같이 보인다
9. **내보내기** — 프롬프트 / CSS 변수 / Tailwind / JSON 복사, 붙여 넣은 값이 화면의 HEX와 같다
10. **저장 / 서랍** — 저장 → 서랍에서 불러오기 → 수정 → 저장(덮어쓰기), 새로고침 뒤에도 남아 있다
11. **새로고침 / 뒤로 가기** — 새로고침하면 하던 화면 복원, 뒤로 가기로 첫 화면
12. **키보드** — Tab으로 주요 버튼을 모두 지나가고 포커스 링이 보인다, Esc로 창이 닫힌다
13. **모션 줄이기** — 개발자 도구에서 `prefers-reduced-motion: reduce`를 켜면 움직임이 꺼진다

## 매번 확인할 것

- 화면이 코드와 다르게 보이면 먼저 캐시를 의심한다: `document.styleSheets`의 규칙 수나 계산된 스타일로 최신 파일이 적용됐는지 확인
- 콘솔 오류: `read_console_messages`로 error/warn이 0개인지 (패턴 예: `error|Error|Uncaught`)
- 네트워크: 사진이 외부로 전송되지 않는지 (`read_network_requests`에서 업로드 요청 없음)
- 브라우저 기본 대화상자(alert/confirm)를 띄우는 동작은 자동화가 멈추므로 누르기 전에 사용자에게 알린다

## 출력 형식

```
## 브라우저 점검 — <Todo 번호 또는 단계> (<날짜>)

환경: Chrome, 127.0.0.1:8000, 커밋 <짧은 해시>

| 시나리오 | 1440 L | 1440 D | 768 L | 390 L | 390 D | 비고 |
| --- | --- | --- | --- | --- | --- | --- |
| 2. 사진 올리기 | ✅ | ✅ | ✅ | ✅ | ✅ | |
| 6. 역할·대비·모드 | ✅ | ❌ | ✅ | ✅ | ❌ | 다크에서 배지 색이 라이트 값 |

콘솔 오류: 0 · 외부 전송: 없음
발견한 문제 → TODO "살아있는 목록"에 추가할 항목: ...
```

- ❌가 있으면 Todo를 완료로 체크하지 않고, 원인을 고친 뒤 해당 칸만 다시 확인한다.
- 실제로 발견한 문제는 `docs/qa/browser-qa-log.md`에 한 줄씩 남긴다. (README "스킬" 항목의 사용 사례)
- 브라우저 도구가 2~3번 연속 실패하면 반복하지 말고 사용자에게 상황을 알리고 직접 확인을 부탁한다.
